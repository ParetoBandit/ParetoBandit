\section{Related Work}
\label{sec:related}

LLM routing has evolved rapidly from cascading heuristics to supervised classifiers, and more recently, to adaptive routing systems. In this section, we situate ParetoBandit within the landscape of these approaches, highlighting the gaps in addressing production non-stationarity and dynamic budget constraints.

\subsection{Static and Supervised Routers}

Early approaches to cost-aware LLM routing relied on static rules or cascading heuristics (e.g., FrugalGPT~\cite{chen2023frugalgpt}), where a system queries models sequentially from cheapest to most expensive, stopping when a predicted quality threshold is met. Recent works have mathematically unified single-model routing and cascading into a single linear optimization problem to maximize quality under a strict budget constraint. While simple to implement, cascades introduce highly variable latency, as complex queries must await sequential failures before reaching a capable model. 

More recent systems formulate routing as a supervised classification or representation learning task trained offline on preference or evaluation data. RouteLLM~\cite{ong2024routellm} uses matrix factorization on pairwise preference data to map queries to models via a cost threshold. GraphRouter~\cite{feng2025graphrouter} constructs a heterogeneous graph over tasks, queries, and LLMs, using edge prediction to estimate per-model quality and cost, allowing it to generalize to newly added LLMs. Contrastive approaches have also gained traction: CSCR (Cost-Spectrum Contrastive Routing) explicitly penalizes model price during training to push embeddings of cheaper, capable models closer to the prompt, reducing runtime routing to an efficient nearest-neighbor lookup. Similarly, RouterDC~\cite{chen2024routerdc} learns joint embeddings of queries and LLMs via dual contrastive losses. Other architectures use cross-attention mechanisms to explicitly model prompt-LLM feature interactions and predict both response quality and generation cost simultaneously. For theoretical rigor, predictive routers like CARROT jointly forecast accuracy and exact inference cost, providing minimax rate optimality guarantees for worst-case efficiency.

While supervised routers achieve strong performance when deployed on stationary distributions that match their training data, they exhibit two critical flaws in production environments. First, they deploy \emph{frozen policies} that cannot adapt to non-stationarity (e.g., silent model updates or shifting user prompts). Second, they enforce budget constraints via fixed, offline-tuned thresholds or cost penalties. If a model provider unexpectedly drops prices, these static systems fail to dynamically exploit the new cost-quality trade-off, either under-spending their budget or requiring a manual, offline retraining and recalibration cycle.

\subsection{Adaptive and Bandit-Based Routers}

To enable online adaptation, a recent wave of research has formulated LLM routing as a contextual bandit or reinforcement learning (RL) problem, allowing systems to learn continuously from deployment feedback. 

PILOT~\cite{panda2025pilot} extends LinUCB~\cite{li2010contextual} with \emph{preference-prior informed} initialization, injecting LLM embeddings learned offline from human preference data to mitigate the cold-start problem---an instance of the warm-start contextual bandit framework formalised by Kveton et~al.~\cite{kveton2023warmstart}.  Recent work has also explored using LLMs themselves to generate priors that jump-start bandit learning~\cite{pan2024cbli}.  ParetoBandit adopts the same offline-to-online warm-start strategy, initialising the LinUCB sufficient statistics from a labeled reward dataset (Section~\ref{sec:setup}), but differs from PILOT in two respects: it uses a continuous multi-factor reward signal rather than pairwise preferences, and it exposes the prior strength ($n_\mathit{eff}$) as a tunable hyperparameter that controls the explore--exploit balance at initialisation (Section~\ref{sec:exp4_hparam_sweep}).
To manage costs, PILOT employs an online multi-choice knapsack algorithm to optimize cumulative cost over a known, finite horizon. While theoretically grounded, the knapsack approach requires knowing the total number of queries in advance, making it difficult to apply to open-ended, continuous production streams where request volume fluctuates.  Furthermore, PILOT uses standard LinUCB with infinite memory and provides no mechanism for non-stationarity; when a model silently degrades or a provider drops prices, the router cannot adapt without manual intervention.

BaRP~\cite{wang2025barp} trains a contextual bandit using entropy-regularized policy gradients, conditioning routing on a user preference vector to allow inference-time adjustments to the cost-quality trade-off. LLM Bandit~\cite{li2025llmbandit} utilizes a multi-armed bandit with preference-conditioned routing, incorporating model identity vectors to generalize to unseen models. xRouter~\cite{qian2025xrouter} takes an RL approach, fine-tuning a small language model to act as an orchestration agent that decides whether to answer locally or invoke external APIs based on task complexity. Bandit algorithms have also been applied to ensembling: CaMVo uses a LinUCB bandit to dynamically select a subset of models to vote on an answer, halting the routing once a confidence threshold is met to save budget. Finally, recent work on contextual queueing bandits (e.g., ACQB~\cite{bae2026learning}) leverages implicit feedback from user retrials to jointly optimize routing and scheduling in conversational services.

\subsection{Positioning ParetoBandit}

ParetoBandit builds upon the foundation of contextual bandits but introduces critical structural advances designed specifically for the realities of open-ended, budget-constrained production environments:

\begin{enumerate}[leftmargin=*,nosep]
    \item \textbf{Continuous Budget Pacing:} Unlike PILOT's finite-horizon knapsack---which requires knowing the total number of queries $T$ in advance---or the static scalarized cost penalties used in RouteLLM and BaRP, ParetoBandit enforces a per-request average cost rate target via an online Primal-Dual Lagrangian relaxation (adapting the dual-variable mechanism of Agrawal and Devanur~\cite{agrawal2014bandits} from a cumulative knapsack constraint to a rate constraint suitable for open-ended production streams).  This \emph{BudgetPacer} strictly enforces a per-request average cost target (e.g., ``\$0.005 per request'') over an unbounded horizon, automatically adjusting to price drops or traffic shifts without offline recalibration.
    \item \textbf{Explicit Handling of Non-Stationarity:} While existing bandit routers continuously learn, they employ infinite memory (e.g., standard LinUCB) and evaluate exclusively under stationary conditions---model quality and pricing are held fixed throughout the entire experimental trajectory~\cite{panda2025pilot,wang2025barp,li2025llmbandit}. When model quality degrades (reward drift), infinite memory causes catastrophic inertia, as the router slowly unlearns thousands of stale historical observations. ParetoBandit introduces a principled geometric forgetting mechanism that dynamically discounts stale evidence, enabling rapid adaptation to quality shifts while preserving enough historical context to avoid volatile, uninformed routing. To our knowledge, this work provides the \emph{first} experimental evaluation of LLM router behaviour under reward and cost non-stationarity, adopting the standard three-phase stress-test protocol from the non-stationary bandit literature~\cite{garivier2011switching} (Section~\ref{sec:setup}).
    \item \textbf{Production State Management:} Existing bandit routers maintain learned state exclusively in process memory, making them unable to recover from restarts or incorporate delayed human feedback (RLHF). ParetoBandit provides pluggable context persistence (in-memory or SQLite-backed) for asynchronous feedback ingestion and atomic state checkpointing for crash recovery, bridging the gap between research prototypes and deployable systems (Section~\ref{sec:discussion}).
    \item \textbf{Native $K{\geq}3$ Multi-Model Support:} Most existing routers---both supervised (RouteLLM~\cite{ong2024routellm}) and adaptive (BaRP~\cite{wang2025barp})---are designed around a binary strong/weak decision, using pairwise preference data or binary cost thresholds to triage between exactly two models.  This $K{=}2$ framing limits a router's ability to operate under budget constraints and non-stationarity.  With only two arms, the router has a single lever---what fraction of traffic goes to the expensive model---leaving no room to discover that a mid-tier alternative delivers comparable quality at a fraction of the cost.  When rewards shift or prices drop, a richer portfolio gives the router more options to reallocate traffic and maintain quality within budget; with $K{=}2$, every such event collapses to the same binary trade-off.  ParetoBandit's contextual bandit formulation is natively $K$-armed: each model is an independent arm with its own learned reward surface, the BudgetPacer's Lagrangian penalty operates over the full cost spectrum, and new arms are added at runtime via a single API call without architectural changes (Appendix~\ref{appendix:model_onboarding}).
\end{enumerate}
