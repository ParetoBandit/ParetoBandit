\section{Related Work}
\label{sec:related}

LLM routing has matured from cascading heuristics to supervised classifiers, and recently to bandit-based adaptive routers. We position banditGPT within this landscape, summarized in Table~\ref{tab:comparison}.

\subsection{Static and Supervised Routers}
Early cost-aware routing utilized learned cascades (e.g., FrugalGPT~\cite{chen2023frugalgpt}), which train a scoring function to sequentially query LLMs and stop when predicted quality is sufficient. This reduces average cost but introduces variable latency. More recently, supervised routers train offline on preference or evaluation data to select a single model per query. RouteLLM~\cite{ong2024routellm} (our primary baseline) uses matrix factorization on pairwise preference data to route between a strong and a weak model via a cost-calibrated threshold. GraphRouter~\cite{feng2025graphrouter} constructs a heterogeneous graph over tasks, queries, and LLMs, using GNN edge prediction to estimate per-model quality and cost; notably, its inductive architecture generalizes to newly added LLMs without retraining. RouterDC~\cite{chen2024routerdc} learns query and LLM embeddings via dual contrastive losses, routing to the model with highest embedding similarity. While these systems offer strong out-of-the-box routing when deployment traffic matches the training distribution, their frozen policies cannot adapt to non-stationary deployments (Section~\ref{sec:distribution_shift}) and can exhibit non-monotonic quality-cost behavior due to prompt-level quality inversions that static thresholds fail to capture (Section~\ref{sec:nonmonotone}).

\subsection{Bandit-Based and RL-Based Adaptive Routers}
To enable online adaptation, concurrent works formulate routing as a bandit or reinforcement learning problem. PILOT~\cite{panda2025pilot} is the closest methodological relative to banditGPT: it extends LinUCB with \emph{preference-prior informed} initialization, where LLM embeddings learned offline from ChatArena human preference data are injected into the bandit's sufficient statistics ($A_a{=}\lambda_a I$, $b_a{=}\lambda_a\theta_a^{\mathrm{pref}}$), providing a warm start analogous to banditGPT's warmup priors (Section~\ref{sec:warmup_prior_construction}). PILOT additionally learns a shared query--LLM embedding space via two-phase pretraining (triplet loss for query projections, then binary cross-entropy for LLM embeddings) and couples the bandit with a multi-choice knapsack formulation to optimize cumulative cost over a horizon. We provide a detailed comparison of the two warmup prior mechanisms below (Section~\ref{sec:positioning}) and in Appendix~\ref{appendix:positioning}. BaRP~\cite{wang2025barp} trains a contextual bandit under partial (bandit) feedback using entropy-regularized policy gradients; it conditions routing on a user preference vector, enabling operators to adjust the cost-quality trade-off at inference time without retraining. LLM Bandit~\cite{li2025llmbandit} formulates model selection as a multi-armed bandit with preference-conditioned routing, using model identity vectors to capture per-model capabilities and generalize to unseen LLMs. C2MAB-V~\cite{dai2024c2mab} addresses a distinct problem---selecting \emph{combinations} of LLMs for collaborative tasks via combinatorial bandits---rather than routing each query to a single model. xRouter~\cite{zhang2025xrouter} takes an RL approach, fine-tuning a small LM to serve as both router and responder: it decides whether to answer a query directly or invoke an external model, trained end-to-end with a cost-aware reward.

\subsection{Positioning banditGPT}
\label{sec:positioning}
Both PILOT and banditGPT share the same Bayesian intuition for cold-start reduction: initialize LinUCB's sufficient statistics from offline data so that the arm-parameter posterior starts near a useful estimate rather than at the uninformative origin.
In PILOT, LLM embeddings $\theta_a^{\mathrm{pref}}$ are first learned from ChatArena pairwise comparisons via triplet loss, then injected as $b_a{=}\lambda_a\theta_a^{\mathrm{pref}}$ with $A_a{=}\lambda_a I$, where $\lambda_a$ (the inverse of the arm's pretraining accuracy) controls prior strength.
In banditGPT, prior matrices are accumulated directly from (prompt, model, reward) triples via rank-1 LinUCB updates ($\Amat_m \mathrel{+}= \xvec\xvec^\top$, $\bvec_m \mathrel{+}= r\xvec$), then scaled by a plasticity factor $\rho{=}0.1$ so online data overrides the prior within a few hundred steps.
The key distinction is the \emph{signal type}: PILOT's priors derive from relative preference comparisons (which LLM ``won''), while banditGPT's derive from absolute reward observations, arguably a richer signal since it encodes reward magnitude. Specifically, banditGPT generates online and offline rewards using a multi-judge ensemble that emits continuous scores via confidence-weighted binary votes (i.e., $\text{mean}(v \times c)$). This design aligns with recent trends recognizing the variance and bias of single LLM-as-a-judge evaluators~\cite{zheng2023judging}. While concurrent literature explores uncertainty-aware routing by utilizing judge confidence to reject unreliable model generations or balance cost-efficiency~\cite{zhang2025leveraging}, banditGPT takes a different approach: it directly integrates the ensemble's mean confidence into the bandit's continuous reward magnitude. This provides a richer, more granular signal than binary pairwise preferences, accelerating the bandit's ability to distinguish closely performing models while inherently mitigating the idiosyncratic biases of any single judge.
A second critical distinction is robustness to prior misspecification: PILOT relies solely on $\lambda_a$ tuning, whereas banditGPT hedges through the Corralling meta-learner described below.

Beyond this shared warmup prior capability, banditGPT introduces three structural advances absent from concurrent bandit routers:
\begin{enumerate}[leftmargin=*,nosep]
    \item \textbf{Meta-ensemble via Corralling:} Unlike prior systems using a single policy, banditGPT layers a Corralling meta-learner~\cite{agarwal2017corralling} over two expert bandits (one warm-started, one tabula rasa). This provides a regret-hedging safety mechanism against prior misspecification that standard bandits lack: when priors are well-calibrated, Corralling exploits them for 7--13\% lower regret; when they are misleading, it shifts weight to the tabula rasa expert within ${\sim}50$ decisions (Section~\ref{sec:prior_degradation}). PILOT has no analogous mechanism---if the preference prior is misleading, online learning must overcome it gradually through $\lambda_a$ scaling alone.
    \item \textbf{Hard constraints via budget filtering:} Rather than scalarizing cost into the reward (BaRP) or optimizing over a horizon (PILOT knapsack), banditGPT strictly enforces per-request hard constraints (cost ceiling, latency ceiling, quality floor) by pruning ineligible models before the bandit selects.
    \item \textbf{Family-level parameter sharing:} For larger portfolios ($K \geq 3$), Hybrid LinUCB pools observations across models within the same provider family, improving sample efficiency when per-model data is scarce. No concurrent bandit router exploits cross-model structure at this level.
\end{enumerate}
