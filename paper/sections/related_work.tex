\section{Related Work}
\label{sec:related}

LLM routing has matured from cascading heuristics to supervised classifiers, and recently to bandit-based adaptive routers. We position banditGPT within this landscape, summarized in Table~\ref{tab:comparison}.

\subsection{Static and Supervised Routers}
Early cost-aware routing utilized cascading (e.g., FrugalGPT~\cite{chen2023frugalgpt}), escalating queries to more expensive models until a quality threshold was met. This reduces average cost but introduces non-deterministic latency. More recently, supervised static routers like RouteLLM~\cite{ong2024routellm} (our primary baseline), GraphRouter~\cite{feng2025graphrouter}, and RouterDC~\cite{chen2024routerdc} train offline classifiers to predict the best model per query. While these systems offer strong out-of-the-box routing when deployment traffic matches the training distribution, their frozen policies struggle with non-stationary deployments (Section~\ref{sec:distribution_shift}) and can exhibit non-monotonic quality-cost behavior due to prompt-level quality inversions that static thresholds fail to capture (Section~\ref{sec:nonmonotone}).

\subsection{Bandit-Based Adaptive Routers}
To enable online adaptation, concurrent works formulate routing as a bandit problem. PILOT~\cite{panda2025pilot} refines a shared query-LLM embedding space online via contextual bandits and optimizes cumulative cost over a horizon via a knapsack policy. BaRP~\cite{wang2025barp} trains a contextual bandit under partial feedback using policy gradients, matching deployment constraints where only the selected model's reward is observed. LLM Bandit~\cite{li2025llmbandit} formulates model selection as a multi-armed bandit with preference-conditioned routing, enabling users to specify cost-quality trade-offs at inference time. Other approaches leverage combinatorial multi-armed bandits (C2MAB-V~\cite{dai2024c2mab}) or RL-trained orchestrators (xRouter~\cite{zhang2025xrouter}).

\subsection{Positioning banditGPT}
Like PILOT, banditGPT initializes contextual bandits from offline preference data to reduce cold-start penalties. Beyond this shared capability, banditGPT introduces three structural advances absent from concurrent bandit routers:
\begin{enumerate}[leftmargin=*,nosep]
    \item \textbf{Meta-ensemble via Corralling:} Unlike prior systems using a single policy, banditGPT layers a Corralling meta-learner~\cite{agarwal2017corralling} over two expert bandits (one warm-started, one tabula rasa). This provides a regret-hedging safety mechanism against prior misspecification that standard bandits lack, and pairs naturally with offline-to-online transfer by hedging against prior quality.
    \item \textbf{Hard constraints via budget filtering:} Rather than scalarizing cost into the reward (BaRP) or optimizing over a horizon (PILOT knapsack), banditGPT strictly enforces per-request hard constraints (cost ceiling, latency ceiling, quality floor) by pruning ineligible models before the bandit selects.
    \item \textbf{Family-level parameter sharing:} For larger portfolios ($K \geq 3$), Hybrid LinUCB pools observations across models within the same provider family, improving sample efficiency when per-model data is scarce. No concurrent bandit router exploits cross-model structure at this level.
\end{enumerate}
