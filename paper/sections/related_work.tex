\section{Related Work}
\label{sec:related}

LLM routing has matured rapidly: from early cascading heuristics, through supervised classifiers, to the current wave of bandit-based adaptive routers.
We survey the landscape along two axes---\emph{static vs.\ adaptive} and \emph{cost handling}---and position banditGPT's specific contributions within it.

\subsection{Cascading and Sequential Architectures}

FrugalGPT~\cite{chen2023frugalgpt} pioneered cost-aware routing via cascading: a query is sent to progressively more expensive models until a quality threshold is met.
This reduces average cost but introduces non-deterministic latency (the sum of all attempted inferences) and requires a per-model scoring function.
banditGPT is a single-shot router: it selects one model before inference, guaranteeing deterministic latency.

\subsection{Supervised Static Routers}

A family of recent systems trains classifiers offline to predict the best model per query:

\begin{itemize}[nosep]
    \item \textbf{RouteLLM}~\cite{ong2024routellm} (ICLR 2025) trains Matrix Factorization or BERT classifiers on LMSYS Chatbot Arena preference data, supporting $K{=}2$ (strong/weak) routing via a threshold parameter. It is open-source (4.6k GitHub stars) and serves as our primary baseline.
    \item \textbf{GraphRouter}~\cite{feng2025graphrouter} (ICLR 2025) constructs a heterogeneous graph over tasks, queries, and LLMs, using edge prediction for routing. Its inductive formulation generalizes to new LLMs without retraining.
    \item \textbf{RouterDC}~\cite{chen2024routerdc} (NeurIPS 2024) uses dual contrastive learning on query--LLM embeddings, achieving strong out-of-distribution generalization.
    \item The \textbf{LLMRouter} library~\cite{feng2025llmrouter} unifies 16+ routing strategies (including RouteLLM, GraphRouter, and RouterDC) with a common evaluation harness.
\end{itemize}

These systems provide strong out-of-the-box routing when sufficient labeled data covers the deployment distribution.
Their shared limitation is \emph{static deployment}: once trained, the routing policy is frozen.
As demonstrated in Section~\ref{sec:pareto}, when the deployment distribution diverges from training data---e.g., the ``strong'' model is not uniformly superior---static routers can exhibit non-monotonic cost--quality behavior, paying more for worse quality.
They also require retraining when new models are added.

\subsection{Bandit-Based Adaptive Routers}

A growing body of work applies contextual bandits to LLM routing, enabling online adaptation without full supervision.
We summarize representative systems below; a compact feature comparison table is provided in the supplementary material.

\paragraph{PILOT}~\cite{panda2025pilot} (EMNLP 2025 Findings) learns a shared query--LLM embedding space from offline human preference data and refines it online via LinUCB.
It pairs this with a multi-choice knapsack cost policy for budget-constrained routing over a horizon, optimizing cumulative cost rather than per-request cost.

\paragraph{BaRP}~\cite{wang2025barp} trains a preference-conditioned contextual bandit under partial (bandit) feedback, matching realistic deployment conditions where only the selected model's reward is observed.
Operators can adjust a performance--cost preference vector at inference time without retraining.

\paragraph{LLM Bandit}~\cite{li2025llmbandit} formulates model selection as a preference-conditioned MAB with model identity vectors, enabling generalization to unseen LLMs.
Code is available at \texttt{spotify-research/llm-bandit}.

\paragraph{C2MAB-V}~\cite{dai2024c2mab} extends combinatorial multi-armed bandits to the multi-LLM setting, selecting model subsets for collaborative tasks via integer programming relaxation with online updates.

\paragraph{xRouter}~\cite{zhang2025xrouter} takes a reinforcement learning approach, training a router agent (e.g., Qwen2.5-7B) with an explicit cost-aware reward function to learn end-to-end orchestration strategies.

\subsection{Positioning banditGPT}

banditGPT occupies a specific niche within this landscape.
It is \emph{not} the first bandit-based LLM router---PILOT, BaRP, and LLM Bandit all formulate routing as a contextual bandit problem.
Instead, banditGPT makes three structural contributions that complement rather than supersede this concurrent work:

\paragraph{1.\ Meta-ensemble via Corralling.}
All prior bandit routers use a single contextual bandit policy.
To our knowledge, banditGPT is the first LLM routing system to explicitly layer a Corralling~\cite{agarwal2017corralling} coordinator over two expert contextual bandits with complementary exploration schedules---one initialized from warmup priors and one starting from scratch.
Corralling is motivated by worst-case regret guarantees in its theoretical setting; our implementation uses a simplified, production-oriented variant and we therefore emphasize empirical stress tests under prior mismatch (Section~\ref{sec:prior_degradation}).
In our evaluation, Corralling reduces regret by 29--39\% relative to either expert alone when priors are useful ($\alpha \leq 0.5$).
Subsequent model-selection frameworks~\cite{pacchiano2020model, cutkosky2021dynamic} improve on Corralling's variance guarantees through regret balancing, though none have been applied to LLM routing.

\paragraph{2.\ Offline-to-online prior transfer.}
PILOT learns a shared embedding space from scratch; BaRP trains under bandit feedback.
banditGPT instead initializes LinUCB sufficient statistics ($\Amat, \bvec$) from 80k RouteLLM battle outcomes (or smaller domain-specific evaluation batches for $K{>}2$), then adapts online.
This enables production-quality routing from the first request while the Corralling meta-learner hedges against prior mismatch---a combination that no prior system provides.

\paragraph{3.\ Hard constraints via Dynamic Pareto Filtering.}
PILOT folds cost into a knapsack policy that optimizes over a horizon; BaRP scalarizes cost into the reward.
banditGPT enforces per-request hard constraints (\texttt{max\_cost}, \texttt{max\_latency}, \texttt{quality\_floor}) by pruning dominated models \emph{before} the bandit selects, guaranteeing constraint satisfaction per-request rather than in expectation.

\paragraph{Advantages of concurrent work.}
We note areas where PILOT and BaRP advance beyond banditGPT's current design:
(a)~PILOT's jointly optimized query--LLM embeddings may capture non-linear structure that our fixed PCA pipeline cannot;
(b)~BaRP's per-request preference vector provides finer-grained control than banditGPT's episode-level $\lambda$;
(c)~PILOT's knapsack formulation is better suited for deployments with strict aggregate budget caps.
These suggest natural extensions for future work.
