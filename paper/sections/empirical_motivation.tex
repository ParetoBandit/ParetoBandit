\section{Empirical Motivation: The Semantic Structure of Routing}
\label{sec:motivation}

% TRANSITION from Introduction
Current LLM routers operate under an implicit assumption: task ``difficulty'' determines which model to use---easy tasks go to cheap models, hard tasks to expensive ones. This section presents two empirical findings that overturn this assumption and directly motivate the banditGPT architecture:

\begin{enumerate}
    \item \textbf{Model Preference Heterogeneity (Figure~\ref{fig:alignment_tax}):} The expensive model is not merely unnecessary on some tasks---it is \emph{actively worse} on a specific, identifiable subset. This transforms routing from interpolation (``how much quality am I willing to trade for cost?'') into \textbf{discovery} (``which prompts actually benefit from the expensive model?'').
    
    \item \textbf{Distribution Shift (Section~\ref{sec:distribution_shift}):} The training data over-represents exactly the prompts where the expensive model fails, causing static routers to systematically misroute deployment traffic. This makes safe online learning essential, not optional.
\end{enumerate}

Together, these findings establish: \textbf{routing is a learnable discovery problem, but the training signal is misleading---requiring adaptive mechanisms with safety guarantees.}

\subsection{Cluster Analysis: Model Preference Heterogeneity}

We analyze model preference heterogeneity by projecting 750 held-out prompts from the LMSYS Arena onto the first principal component (PC1) of a 32-component PCA model trained on sentence embeddings from 80K routing prompts. This domain-adapted PCA is \emph{unsupervised}---it never sees reward labels during training---and identifies directions of maximum variance in routing-relevant prompt space.

The cluster boundary at $\text{PC1} = 0.222$ was selected using a purely unsupervised method: silhouette-optimal threshold search over PC1 values, maximizing geometric cluster quality without reference to reward labels (silhouette score = 0.499). This avoids the methodological concern of threshold selection bias from reward peeking. Examining the ground-truth reward gaps within these clusters reveals a \textbf{performance inversion} that contradicts standard ``complexity'' assumptions (Table~\ref{tab:cluster_inversion}).

\paragraph{The Low PC1 Cluster (80.8\%, $n=606$).}
The majority cluster contains diverse conversational prompts where the frontier model's superior instruction following and world knowledge yield a moderate advantage ($+0.121$, 95\% CI: $[+0.088, +0.153]$). A naive router that offloads this entire cluster to Mixtral would degrade performance. banditGPT succeeds by preserving this cluster for the expensive model while routing strict-constraint tasks to cheaper alternatives.

\paragraph{The High PC1 Cluster (19.2\%, $n=144$).}
A minority cluster shows a substantial \emph{performance inversion}: the cheaper model significantly outperforms the frontier ($-0.563$, 95\% CI: $[-0.661, -0.464]$). Qualitative inspection reveals this cluster is dominated by strict formatting constraints---instruction-following templates, binary classification tasks, and structured output requirements. We observe that the frontier model's conversational tendencies (e.g., adding preambles, explaining reasoning) correlate with violations of strict formatting requirements, while the open-weights model adheres more closely to template structure.

\textit{Representative examples from this cluster include:}
\begin{itemize}[noitemsep,topsep=2pt,leftmargin=10pt]
    \item \textbf{Instruction-following templates:} ``Below is an instruction that describes a task, paired with an input that provides further context. Write a response that appropriately completes the request. \#\#\# Instruction: [...]'' (Gap: $-1.0$)
    \item \textbf{Binary classification:} ``Given the document below, you have to determine if `Yes' or `No', the summary is factually consistent [...]'' (Gap: $-1.0$)
    \item \textbf{Structured output constraints:} ``I want you to act as an aspect-based sentiment analysis model [...] The sentiment should be either positive, negative or neutral.'' (Gap: $-1.0$)
    \item \textbf{Explicit negative constraints:} ``Use the following pieces of context to answer the question. If you don't know the answer, just say that you don't know, don't try to make up an answer.'' (Gap: $-1.0$)
\end{itemize}

We note that while these patterns are consistent with the hypothesis that RLHF alignment toward helpfulness may conflict with strict formatting constraints, \textbf{this causal mechanism has not been verified through controlled experiments} (e.g., comparing RLHF-tuned vs.\ base model responses). Alternative explanations---such as differences in instruction-following fine-tuning, decoding strategies, or evaluator biases---remain possible.

\paragraph{Statistical Validation.}
The difference between clusters is highly significant (Mann-Whitney $U$: $p < 0.0001$, Cohen's $d = 1.53$, large effect). The 95\% confidence intervals do not overlap. All analyses use the held-out test set exclusively ($N=750$), with the PCA model trained on a disjoint set of 80K prompts and the cluster threshold determined by purely unsupervised geometric criteria.

\paragraph{Robustness: PCA Provenance Sensitivity.}
To validate that this finding is not an artifact of domain-adapted PCA, we repeat the analysis with PCA trained on 100K generic web text samples (C4 corpus), which has no connection to routing. The effect persists ($p < 0.0001$, Cohen's $d = 0.33$), confirming that the underlying structure exists in the embedding space independently of PCA provenance. The domain-adapted PCA concentrates routing-relevant variation more efficiently into PC1 ($d = 1.53$ vs.\ $0.33$), consistent with its training on routing-relevant prompts. This 4.6$\times$ difference in effect size demonstrates that PCA provenance significantly influences the sharpness of the detected structure, but the phenomenon is real under both feature extraction approaches. We emphasize that the domain-adapted PCA is the appropriate tool for routing analysis, analogous to training on domain-specific data for any supervised learning task; the generic PCA serves as a robustness check confirming independence from PCA training data.

\paragraph{Methodological Notes.}
\begin{itemize}[noitemsep,topsep=2pt,leftmargin=10pt]
    \item \textbf{Data:} Held-out test set only ($N=750$). The dev set ($N=1{,}121$), used for online learning in Table~\ref{tab:performance_gap}, is excluded to maintain train/test independence.
    \item \textbf{PCA:} Domain-adapted, trained on 80K routing prompt embeddings (unsupervised---no reward labels). Applied to disjoint held-out data.
    \item \textbf{Threshold:} Silhouette-optimal ($\text{PC1} = 0.222$, silhouette $= 0.499$), selected without reference to reward labels.
    \item \textbf{Reward source:} LMSYS Chatbot Arena human preference evaluations~\cite{zheng2023judging}, based on side-by-side model comparisons by crowd-workers.
    \item \textbf{High-dimensional structure:} The 384D silhouette score is 0.057 (weak), indicating that clusters overlap substantially in the full embedding space. The PC1 projection isolates a task-relevant axis from a noisy high-dimensional space (Spearman $\rho = -0.395$, $\rho^2 = 0.156$, explaining $\sim$16\% of reward gap variance---a moderate correlation).
    \item \textbf{Cluster diversity:} High PC1 diversity = 0.355 (average pairwise cosine similarity 0.645), indicating a relatively homogeneous cluster consistent with a coherent semantic category of strict-format prompts, rather than a broad phenomenon across diverse prompt types.
\end{itemize}

\paragraph{Why This Matters for Routing.}
This finding has three direct consequences for router design:

\begin{enumerate}[noitemsep,topsep=2pt]
    \item \textbf{Static ``hardness'' classifiers will fail.} A router trained to predict task difficulty and send ``hard'' prompts to the expensive model will systematically over-provision GPT-4 on the strict-constraint subset where it underperforms. This is precisely what we observe in the Pareto analysis (Section~\ref{sec:pareto}): RouteLLM's performance \emph{degrades} as it routes more traffic to GPT-4, ultimately paying $43\times$ more for $1.3\%$ lower quality.
    
    \item \textbf{The routing opportunity is counter-intuitive.} Cost savings do not come from offloading ``easy'' tasks to cheap models. They come from \emph{discovering} the specific subset where the expensive model is actively worse---a structure that must be learned from data, not assumed from complexity heuristics.
    
    \item \textbf{Online learning is essential.} Because this structure is counter-intuitive and varies with deployment distribution, it cannot be reliably specified a priori. banditGPT learns this preference structure online, using GPT-4 only when statistically justified by observed rewards.
\end{enumerate}

\subsection{Scale Validation}

To examine whether the spatial structure persists at scale, we projected the complete LMSYS Chat-1M dataset (594,199 unique prompts) onto our PCA space.

The principal component structure exhibits stability: PC1 variance remains at $3.10\%$ and the spatial distribution shows $94.1\%$ Low PC1 vs.\ $5.9\%$ High PC1 (Table~\ref{tab:spectral}). However, \textbf{the 1M dataset lacks reward labels}, so we cannot validate whether the reward-preference correspondence persists at scale. The stability of spatial structure is expected (PCA is a fixed linear projection applied to embeddings from the same model), and should not be interpreted as evidence that the performance inversion generalizes to unlabeled production traffic.

\subsection{Distribution Shift: Motivating Adaptive Learning}
\label{sec:distribution_shift}

A fundamental risk in routing is \textbf{Covariate Shift}: when the distribution of tasks at deployment differs from the offline training data, priors can become harmful. We quantified this shift using the Population Stability Index (PSI), obtaining $\text{PSI} = 0.275$ (95\% CI: $[0.243, 0.332]$), which exceeds the standard threshold for substantial shift ($>0.25$). Kolmogorov-Smirnov testing confirms the distributions are significantly different ($p < 10^{-37}$, Cohen's $d = -0.35$).

\paragraph{Important caveat: dataset heterogeneity, not production drift.}
This shift is measured between two different data collections---the LMSYS dev/holdout set and RouteLLM battle data---which were gathered under different sampling procedures, time periods, and selection criteria. We therefore characterize this as \emph{dataset heterogeneity} rather than a measured ``production drift.'' While this heterogeneity is representative of the kind of distributional mismatch that arises in real deployments (where training and serving distributions inevitably differ), we cannot claim it precisely mirrors any specific production scenario. The magnitude of the shift motivates adaptive mechanisms, but the exact PSI value is specific to these two dataset collections.

Critically, the \emph{direction} of the shift compounds the danger. Offline training data over-indexes on High PC1 prompts, where Mixtral is preferred. The holdout distribution is predominantly Low PC1, where GPT-4 excels. A static router trained on the offline distribution therefore learns to be systematically pessimistic about GPT-4's utility on the dominant evaluation traffic---creating a ``False Negative'' policy that underestimates GPT-4 precisely where it should be deployed.

This motivates the \textbf{tabula rasa} expert in our Corralling framework (Section~\ref{sec:methodology}), which learns deployment-specific preferences unburdened by this offline bias. For shifts of this magnitude (PSI$\geq$0.25), the system requires adaptive mechanisms with safety guarantees, as static priors become actively harmful. We note that the prescriptive PSI thresholds used here (PSI$<$0.1 for safe exploitation, PSI$\geq$0.25 for requiring unlearning) follow standard industry conventions from credit risk modeling but have not been independently validated for the LLM routing domain; future work should calibrate domain-specific thresholds on held-out deployment data. Full distribution shift visualization and decomposition are provided in Appendix~\ref{app:distribution_shift}.

\subsection{Synthesis: From Observation to Architecture}

The two findings above form a coherent argument for adaptive routing:

\begin{enumerate}[noitemsep,topsep=2pt]
    \item \textbf{Structure exists} (Section~\ref{sec:motivation}): Model preference heterogeneity is real and learnable through prompt embeddings ($p < 0.0001$, $d = 1.53$). A router equipped with the right features \emph{can} distinguish prompts that benefit from the expensive model from those that do not.
    
    \item \textbf{But static priors mislead} (Section~\ref{sec:distribution_shift}): The training distribution over-represents the inversion subset (High PC1), causing static routers to learn a policy that is \emph{directionally wrong} on deployment traffic. Simply learning the structure offline is insufficient---the router must adapt to the deployment distribution.
    
    \item \textbf{Therefore, safe online learning is necessary:} The router must (a) exploit semantic structure to make the preference discovery tractable, (b) hedge against misleading priors via meta-learning, and (c) handle non-stationarity as new models enter the portfolio. These are exactly the three mechanisms of banditGPT (Section~\ref{sec:methodology}).
\end{enumerate}

This chain---from empirical observation, through failure analysis of static methods, to architectural requirements---is the foundation for the system we present next.
