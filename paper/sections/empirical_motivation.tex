\section{Empirical Motivation: The Semantic Structure of Routing}
\label{sec:motivation}

% TRANSITION from Introduction
Current LLM routers operate under an implicit assumption: task ``difficulty'' determines which model to use---easy tasks go to cheap models, hard tasks to expensive ones. This section presents an empirical finding that overturns this assumption and directly motivates the banditGPT architecture:

\textbf{Model Preference Heterogeneity (Figure~\ref{fig:lmsys_holdout_structure}):} The expensive model is not merely unnecessary on some tasks---it is \emph{actively worse} on a specific, identifiable subset. This transforms routing from interpolation (``how much quality am I willing to trade for cost?'') into \textbf{discovery} (``which prompts actually benefit from the expensive model?'').

This finding establishes: \textbf{routing is a learnable discovery problem requiring adaptive mechanisms with safety guarantees.}

\subsection{Model Preference Heterogeneity}

We analyze model preference heterogeneity by projecting 750 held-out prompts from the LMSYS Arena onto the first principal component (PC1) of a 32-component PCA model trained on sentence embeddings from 80K routing prompts. This domain-adapted PCA is \emph{unsupervised}---it never sees reward labels during training---and identifies directions of maximum variance in routing-relevant prompt space.

\paragraph{Features predict model preference.}
The router's PC1 shows a significant Spearman rank correlation with the reward gap $(R_{\text{GPT-4-Turbo}} - R_{\text{Mixtral}})$: $\rho = -0.370$, $p < 0.0001$, $N = 750$ (Figure~\ref{fig:lmsys_holdout_structure}A). The negative correlation means higher PC1 values correspond to prompts where the cheaper model (Mixtral) outperforms GPT-4-Turbo---exactly the signal a contextual bandit needs to learn routing.

To confirm this is genuine signal rather than a projection artifact, we compare the Router PCA's $|\rho| = 0.370$ against 100 independent random orthonormal projections ($384 \to 2$, QR-decomposed). The Router PCA exceeds all 100 random projections (Figure~\ref{fig:lmsys_holdout_structure}B), with a 2.6$\times$ signal ratio versus the random median ($|\rho|_{\text{random}} = 0.145$).

\paragraph{Model preference is heterogeneous.}
The outcome distribution reveals that model preference is not uniform (Table~\ref{tab:outcome_distribution}). The majority of prompts are ties where both models perform comparably. This heterogeneity is what makes contextual routing valuable: a static policy cannot be optimal when preferences vary by prompt.

\paragraph{What the PCA captures.}
Qualitative inspection of prompts at the high end of the PC1 axis---where Mixtral preference is strongest---reveals enrichment for strict formatting constraints. These prompts share a common structure: explicit instructions with constrained output format.

\textit{Representative examples:}
\begin{itemize}[noitemsep,topsep=2pt,leftmargin=10pt]
    \item \textbf{Instruction-following templates:} ``Below is an instruction that describes a task, paired with an input that provides further context. Write a response that appropriately completes the request. \#\#\# Instruction: [...]'' (Gap: $-1.0$)
    \item \textbf{Binary classification:} ``Given the document below, you have to determine if `Yes' or `No', the summary is factually consistent [...]'' (Gap: $-1.0$)
    \item \textbf{Structured output constraints:} ``I want you to act as an aspect-based sentiment analysis model [...] The sentiment should be either positive, negative or neutral.'' (Gap: $-1.0$)
    \item \textbf{Explicit negative constraints:} ``Use the following pieces of context to answer the question. If you don't know the answer, just say that you don't know, don't try to make up an answer.'' (Gap: $-1.0$)
\end{itemize}

We note that while these patterns are consistent with the hypothesis that RLHF alignment toward helpfulness may conflict with strict formatting constraints, \textbf{this causal mechanism has not been verified through controlled experiments} (e.g., comparing RLHF-tuned vs.\ base model responses). Alternative explanations---such as differences in instruction-following fine-tuning, decoding strategies, or evaluator biases---remain possible.

\paragraph{Statistical Validation.}
The Spearman correlation ($\rho = -0.370$, $p < 0.0001$) is the primary metric, chosen because it directly tests the question the bandit needs answered: do the features predict model preference? This matches how BanditGPT uses features (LinUCB regression), without introducing artificial clustering or thresholds. PC1 is a conservative lower bound on the full feature vector's predictive power, since the router uses all 32 PCA components.

A supplementary Mann-Whitney $U$ test on a median split of PC1 confirms the directional finding ($p < 0.0001$). All analyses use the held-out test set exclusively ($N=750$), with the PCA model trained on a disjoint set of 80K prompts.

\paragraph{Methodological Notes.}
\begin{itemize}[noitemsep,topsep=2pt,leftmargin=10pt]
    \item \textbf{Data:} Held-out test set only ($N=750$). The dev set ($N=1{,}121$), used for online learning, is excluded to maintain train/test independence.
    \item \textbf{PCA:} Domain-adapted, trained on 80K routing prompt embeddings (unsupervised---no reward labels). Applied to disjoint held-out data.
    \item \textbf{Metric:} Spearman rank correlation, appropriate for ordinal/discrete data ($\{-1, 0, +1\}$) with no distributional assumptions.
    \item \textbf{Reward source:} LMSYS Chatbot Arena human preference evaluations~\cite{zheng2023judging}, based on side-by-side model comparisons by crowd-workers.
    \item \textbf{Stratification caveat:} The holdout was constructed via stratified sampling including a difficulty dimension derived from oracle reward statistics (Appendix~\ref{app:stratification}). This enriches for prompts with clear model preferences. The correlation's \emph{existence} is robust (exceeds all 100 random projections); its \emph{magnitude} in deployment will depend on the user's prompt distribution.
\end{itemize}

\paragraph{Why This Matters for Routing.}
This finding has three direct consequences for router design:

\begin{enumerate}[noitemsep,topsep=2pt]
    \item \textbf{Static ``hardness'' classifiers will fail.} A router trained to predict task difficulty and send ``hard'' prompts to the expensive model will systematically over-provision GPT-4 on the strict-constraint subset where it underperforms. This is precisely what we observe in the Pareto analysis (Section~\ref{sec:pareto}): RouteLLM's performance \emph{degrades} as it routes more traffic to GPT-4, ultimately paying $43\times$ more for $1.3\%$ lower quality.
    
    \item \textbf{Cost savings come from ties.} The majority of prompts (72.8\%) show no strong model preference, meaning the cheaper model can serve them with comparable quality. The router's value is correctly identifying the minority where the expensive model genuinely matters.
    
    \item \textbf{Online learning is essential.} Because the preference structure varies with deployment distribution and is counter-intuitive (the expensive model is \emph{worse} on some prompts), it cannot be reliably specified a priori. banditGPT learns this preference structure online, using GPT-4 only when statistically justified by observed rewards.
\end{enumerate}

\subsection{From Observation to Architecture}

The analysis above motivates adaptive routing through a direct argument:

\begin{enumerate}[noitemsep,topsep=2pt]
    \item \textbf{Structure exists:} Model preference heterogeneity is real and predictable through prompt embeddings ($\rho = -0.370$, $p < 0.0001$, exceeding all 100 random projections). A router equipped with the right features \emph{can} distinguish prompts that benefit from the expensive model from those that do not.
    
    \item \textbf{But static policies cannot exploit it:} Because the preference structure is counter-intuitive (the expensive model is \emph{worse} on some prompts) and varies with deployment distribution, it cannot be reliably specified a priori. A static router trained on offline data risks learning systematically wrong preferences. This is precisely what we observe in the Pareto analysis (Section~\ref{sec:pareto}): RouteLLM's performance \emph{degrades} as it routes more traffic to GPT-4, paying $43\times$ more for $1.3\%$ lower quality.
    
    \item \textbf{Therefore, safe online learning is necessary:} The router must (a) exploit semantic structure to make the preference discovery tractable, (b) hedge against misleading priors via meta-learning, and (c) handle non-stationarity as new models enter the portfolio. These are exactly the three mechanisms of banditGPT (Section~\ref{sec:methodology}).
\end{enumerate}

This chain---from empirical observation, through failure analysis of static methods, to architectural requirements---is the foundation for the system we present next.
