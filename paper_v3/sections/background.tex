\section{Background and Problem}
\label{sec:background}

We formalize LLM routing as an online decision-making problem that must simultaneously learn which model to dispatch, enforce a dollar budget in closed loop, and adapt when model quality or pricing changes after deployment. This section defines the three components of the problem; Section~\ref{sec:system_design} presents our solution.

\subsection{Contextual Bandit Routing}
\label{sec:bandit_routing}

At each discrete step $t = 1, 2, \ldots$, a user prompt arrives and the router observes a context vector $x_t \in \mathbb{R}^d$ representing its content. The router selects a single model $a_t$ from a portfolio $\mathcal{A} = \{1, \ldots, K\}$ and dispatches the prompt. After inference, the system observes a scalar reward $r_t$ reflecting response quality and a realized cost $c_t$ in dollars. The reward may be derived from an automated LLM judge, explicit user feedback, or a task-completion metric; in our setup it is a continuous score normalized to $[0, 1]$ by the judge rubric (Section~\ref{sec:eval_setup}). The objective is to learn a policy $\pi$ that maximizes cumulative quality subject to a constraint on average cost per request (formalized in Section~\ref{sec:budget_constraint}):
\begin{align}
    &\max_{\pi}\; \mathbb{E}\!\left[\sum_{t=1}^{T} r_{t,\,\pi(x_t)}\right]
    \label{eq:objective} \\
    &\text{s.t.}\quad
    \limsup_{T \to \infty}\;\tfrac{1}{T}\textstyle\sum_{t=1}^{T} c_{\pi(x_t)} \leq B
    \notag
\end{align}
where $B$ is the operator's target average cost per request in dollars (e.g., \$0.005/req).
Rather than solving this constrained problem directly, we relax it via a Lagrange multiplier $\lambda_t$ that converts the budget constraint into a per-request cost penalty. At each step the router selects the model with the highest \emph{utility}: predicted reward, plus an exploration bonus for uncertain models, minus $\lambda_t$ times the model's cost. The dual variable $\lambda_t$ rises when recent spending exceeds $B$ and falls when it is below, automatically steering the router toward budget compliance. Section~\ref{sec:system_design} presents the full scoring function and the dynamics of $\lambda_t$.

The router operates under \emph{bandit feedback}~\cite{lattimore2020bandit}: it observes the reward and cost only for the model it dispatched, never the counterfactual outcomes for the $K{-}1$ alternatives. This partial observability is inherent to LLM serving, where evaluating a single prompt already incurs inference cost, and evaluating every model on every prompt would multiply cost by $K$.

Conditioning on the prompt is essential. A context-free router must commit to a fixed traffic distribution regardless of prompt difficulty, wasting frontier calls on easy prompts where a cheap model suffices and under-serving hard prompts that justify the cost premium. A contextual policy learns \emph{which} prompt types each model excels at~\cite{li2010contextual}, reserving expensive calls for prompts where they yield the largest quality gain. This selective spending is what enables a router to approach the quality-cost Pareto frontier under a budget.

\subsection{Context Representation}
\label{sec:context_repr}

The context vector $x_t$ is constructed by a three-stage pipeline. First, the prompt text is encoded into a 384-dimensional dense embedding by a lightweight sentence encoder (all-MiniLM-L6-v2~\cite{reimers2019sentence}). Second, a PCA projection fitted on ${\sim}46{,}000$ disjoint LMSYS Arena prompts reduces the embedding to 25 principal components, retaining ${\sim}28.5\%$ of cumulative variance. The PCA coordinates are whitened to unit variance so that a single isotropic regularizer in the bandit's ridge regression treats all semantic directions equally. Third, a constant bias term is appended, yielding a final feature vector of dimension $d = 26$.

This compression is critical for routing latency. The bandit's per-step cost scales as $O(d^2)$ (Section~\ref{sec:system_design}), so reducing $d$ from 384 to 26 yields a ${\sim}220{\times}$ speedup in matrix operations. At $d{=}26$, the bandit's route-and-update cycle completes in $39\,\mu$s on a single CPU core. Including the sentence-embedding and PCA projection steps, the full end-to-end routing pipeline takes ${\sim}8$\,ms (Appendix~\ref{sec:latency_benchmark}), adding ${<}\,1\%$ overhead to a typical ${\sim}1$\,s model inference call. Although 25 components retain only ${\sim}28.5\%$ of total embedding variance, all routing results reported in Section~\ref{sec:evaluation} are achieved at this dimensionality, demonstrating that the leading principal components capture the prompt-level variation that drives inter-model reward differences.

\subsection{Budget Constraint}
\label{sec:budget_constraint}

Each model $a \in \mathcal{A}$ incurs a deterministic cost $c_a(x_t)$ per request, typically computed from per-token API pricing. In a realistic portfolio, costs span orders of magnitude: the three-tier pool used in our experiments ranges from \$0.00003/req (Llama-3.1-8B) to \$0.015/req (Gemini-2.5-Pro), a $530{\times}$ spread.

The rate constraint in Eq.~\ref{eq:objective} is a deliberate departure from the classical Contextual Bandits with Knapsacks (CBwK) framework~\cite{agrawal2014bandits}, which imposes a cumulative budget $\sum_{t=1}^{T} c_t \leq B_{\mathrm{total}}$ over a known, finite horizon $T$. The cumulative formulation requires the operator to specify a total dollar pool and to know (or estimate) the number of requests in advance; it also updates the dual variable relative to the remaining budget fraction, so it cannot be applied without a horizon. Production LLM serving is open-ended: request volume is unknown and variable, and the natural operational specification is a cost \emph{rate} (dollars per request), not a finite pool. Our rate formulation is horizon-free and self-regulates at any traffic volume without requiring $T$ as input.

We enforce the rate constraint through the dual variable $\lambda_t$ introduced in Section~\ref{sec:bandit_routing}. After each request, a smoothed dual-ascent update adjusts $\lambda_t$ based on how recent spending compares to the target:
\begin{align}
    \bar{c}_t &= (1 - \alpha_{\mathrm{ema}})\,\bar{c}_{t-1}
                 + \alpha_{\mathrm{ema}}\,c_t
    \label{eq:cost_ema} \\
    \lambda_{t+1} &= \bigl[\lambda_t + \eta\,(\bar{c}_t / B - 1)\bigr]_{0}^{\bar\lambda}
    \label{eq:dual_update}
\end{align}
where $\bar{c}_t$ is an EMA-smoothed cost signal ($\alpha_{\mathrm{ema}}{=}0.05$, half-life ${\approx}14$ requests), $\eta{=}0.05$ is the learning rate, and $[\cdot]_0^{\bar\lambda}$ denotes projection onto $[0, \bar\lambda{=}5]$. The EMA is critical: model costs span $530{\times}$, so a single expensive request would cause sawtooth oscillations in $\lambda_t$ if the raw cost were used directly. Normalizing the gradient by $B$ makes $\eta$ portfolio-independent, and the capacity cap $\bar\lambda$ prevents unbounded growth. When $\bar{c}_t / B > 1$ (overspending), the gradient is positive and $\lambda_t$ rises, penalizing expensive models; when $\bar{c}_t / B < 1$ (underspending), the gradient is negative and $\lambda_t$ falls, releasing the router to pursue higher quality. Section~\ref{sec:system_design} details the full scoring function and the two-layer enforcement mechanism (soft penalty plus hard cost ceiling) that operationalize $\lambda_t$.

\subsection{Non-Stationarity}
\label{sec:nonstationarity}

Two forms of environment drift can occur in production LLM deployments: providers silently update models~\cite{chen2023chatgptdrift}, and API pricing changes abruptly (e.g., Google cut Gemini~1.5~Flash prices by 78\% overnight~\cite{google2024flashpricing}). A router that cannot detect and adapt to these shifts will either degrade quality or waste budget, making robust non-stationarity handling an important design requirement.

\paragraph{Reward drift (quality shifts).}
When a provider updates a model behind its API~\cite{ma2024prompt}, the conditional expected reward $f_a(x) = \mathbb{E}[r_t \mid x_t{=}x,\, a_t{=}a]$ changes at some unknown time $\tau$, with $f_a^{(t < \tau)}(x) \neq f_a^{(t \geq \tau)}(x)$. These shifts can be subtle and persistent: Anthropic's September 2025 post-mortem~\cite{anthropic2025postmortem} documented three overlapping infrastructure bugs that degraded Claude quality for weeks, with intermittent recovery masking the problem in aggregate metrics. A router with infinite memory will take hundreds or thousands of new observations to override its stale estimates, continuing to send traffic to a degraded model long after the shift.

\paragraph{Cost drift (price drops).}
When $c_a(x)$ decreases at time $\tau$ (e.g., the OpenAI and Google price cuts cited above~\cite{openai2025turbopricing}), a router with a fixed policy pockets the savings but fails to recognize that model $a$ is now a better value. An adaptive router should reinvest the freed budget into higher-quality models, maximizing quality while remaining at the budget target $B$.

\paragraph{Interaction of the two drift types.}
Reward and cost drift interact: a price drop changes which models are cost-effective, so the router must jointly re-learn reward estimates \emph{and} re-optimize the quality-cost frontier. Non-stationary bandit theory provides tools for this setting, including geometric discounting~\cite{garivier2011switching} and weighted ridge regression~\cite{russac2019weighted}, but these mechanisms have not previously been applied to LLM routing (Section~\ref{sec:intro}, Gap~2). More broadly, concept drift~\cite{gama2014survey} is a well-studied challenge in deployed ML systems; the LLM routing domain introduces the additional complication that both the reward surface and the cost surface can shift independently and simultaneously. Section~\ref{sec:system_design} presents our approach: geometric forgetting on the bandit's sufficient statistics, which gives the router a bounded memory window that tracks both types of drift.
