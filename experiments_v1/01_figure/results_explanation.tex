\subsection{Routing Signal Validation}
\label{sec:semantic_structure}

Before presenting our routing algorithm, we establish empirically that the router's feature extraction pipeline captures genuine model preference signal---a necessary precondition for learned routing to outperform static model selection.

\paragraph{Why this experiment matters.}
BanditGPT routes prompts between models using PCA-compressed sentence embeddings as context for a LinUCB bandit (Section~\ref{sec:method}).
If this feature space contains no signal about which model will perform better on a given prompt, the bandit reduces to random assignment regardless of how much data it collects.
This experiment validates, on held-out data, that the \emph{same PCA used in the production router} separates prompts with different model preferences---and compares that signal against a null baseline to rule out projection artifacts.

\paragraph{Setup.}
We project $N=750$ held-out prompts through three feature extraction conditions using the same sentence encoder (\texttt{all-MiniLM-L6-v2}) deployed in the router:
\begin{enumerate}[noitemsep,topsep=2pt]
    \item \textbf{Router PCA} (domain-adapted): trained on 80K prompts from the \texttt{routellm/gpt4\_judge\_battles} HuggingFace dataset. This is the same PCA deployed in the production \texttt{FeatureService} pipeline.
    \item \textbf{Generic PCA}: trained on 100K C4 web text samples with no routing connection, providing an unbiased baseline.
    \item \textbf{Random projection}: a random orthonormal matrix ($384 \to 2$), providing a null baseline that quantifies how much structure any linear projection finds by chance.
\end{enumerate}
\noindent\textbf{Data independence.}
The PCA training data (RouteLLM battles) and the held-out evaluation data (LMSYS general prompts) originate from \emph{different data sources, different sampling periods, and different prompt populations}.
They share the same model pair but are otherwise independent collections---the PCA has never seen any evaluation prompt.
No decontamination step is needed; the datasets are disjoint by provenance.

For each condition, we cluster on PC1 using a silhouette-optimal threshold (selected without reference to reward labels) and test whether the resulting clusters have different win/tie/loss distributions.
Reward gaps are discrete pairwise outcomes from LMSYS Chatbot Arena human preference evaluations: GPT-4-Turbo win ($\Delta = +1$), tie ($\Delta = 0$), or Mixtral win ($\Delta = -1$).

\paragraph{Primary effect sizes.}
Since outcomes are categorical (win/tie/loss), we report categorical effect sizes as the primary analysis:
\begin{itemize}[noitemsep,topsep=2pt]
    \item \textbf{Cram\'er's $V$}: measures association strength in the $2 \times 3$ contingency table (cluster $\times$ outcome).
    \item \textbf{Odds ratio} (Mixtral win, High vs.\ Low PC1): quantifies how much more likely Mixtral is to win in the High PC1 region.
    \item \textbf{Risk difference} (Mixtral win rate): the absolute difference in Mixtral win probability between regions.
\end{itemize}
We use a permutation test ($n=10{,}000$) to obtain distribution-free $p$-values: reward labels are shuffled while cluster assignments are held fixed, yielding the null distribution of Cram\'er's $V$ under the hypothesis of no association.

\paragraph{Model preference heterogeneity.}
Using the silhouette-optimal threshold on the router PCA, we identify two regions of the PC1 axis with significantly different outcome distributions:

\begin{itemize}[noitemsep,topsep=2pt]
    \item \textbf{Low PC1 (80.8\%, $n=606$):} Diverse prompts dominated by ties ($\sim$82\%), with a modest GPT-4-Turbo advantage ($\sim$15\% GPT-4T wins vs.\ $\sim$3\% Mixtral wins).

    \item \textbf{High PC1 (19.2\%, $n=144$):} Prompts with substantially higher Mixtral win rates ($\sim$62\%) and fewer GPT-4-Turbo wins.
    Systematic TF-IDF analysis of distinctive terms reveals this region is enriched for instruction-following templates, binary classification tasks, and structured output constraints (Appendix~\ref{app:tfidf}).
\end{itemize}

\noindent
The finding is best understood as: \emph{a minority of prompts ($\sim$19\% in the holdout) show strong cheaper-model preference, while the majority show weak or no model differentiation.}
For routing, this means the majority of prompts can be served by the cheaper model with comparable quality, and the router's value is concentrated on avoiding quality loss on the minority where the stronger model matters.

Table~\ref{tab:pca_conditions} compares the effect sizes across feature extraction conditions.
The router PCA captures substantially more routing signal than the random projection null baseline, confirming that the PCA concentrates task-relevant variance rather than projecting noise.
The generic PCA also detects the signal (albeit weaker), confirming the structure exists independently of PCA training domain.

\paragraph{Statistical validation.}
Significance is confirmed by three independent tests:
(1)~$\chi^2$ test of independence on the $2 \times 3$ contingency table ($p < 0.0001$);
(2)~Mann-Whitney $U$-test on ordinal reward gaps ($p < 0.0001$);
(3)~permutation test on Cram\'er's $V$ ($p < 0.0001$, $n=10{,}000$ permutations).
Cohen's $d$ is reported as a supplementary metric for comparability with prior work, but is approximate because the underlying data takes only three discrete values $\{-1, 0, +1\}$; Cram\'er's $V$ and the odds ratio are the appropriate primary effect sizes for this data.

\paragraph{Practical implications for deployment.}
For practitioners deploying BanditGPT:
\begin{enumerate}[noitemsep,topsep=2pt]
    \item \textbf{The router's PCA is not decorative.} It captures genuine routing signal that the bandit can exploit. Without it, the bandit cannot distinguish prompts where a cheaper model suffices.

    \item \textbf{Most prompts are ties.} In the holdout, $\sim$82\% of Low~PC1 prompts show no model preference---meaning the cheaper model can serve them with comparable quality. This is the primary source of cost savings.

    \item \textbf{The routing opportunity is bounded.} Only $\sim$19\% of holdout prompts (possibly $\sim$5.9\% in broader production traffic; see Section~\ref{sec:scale_validation}) fall in the high-signal region. Cost savings scale with this fraction.

    \item \textbf{No contamination concern.} The PCA was trained on 80K RouteLLM battle prompts (\texttt{routellm/gpt4\_judge\_battles}), an entirely separate dataset from the held-out evaluation prompts (LMSYS general prompt pool). The two originate from different data sources, sampling periods, and prompt populations---disjoint by provenance, not by post-hoc filtering.

    \item \textbf{Domain adaptation helps.} The router PCA, trained on routing-domain prompts, captures more signal than generic PCA. Users deploying on a new domain should consider retraining PCA on representative prompts from their traffic.
\end{enumerate}

\paragraph{Methodological notes.}
\begin{itemize}[noitemsep,topsep=2pt]
    \item \textbf{Data:} Held-out test set only ($N=750$), created via stratified sampling (Appendix~\ref{app:stratification}). Dev set excluded.
    \item \textbf{Rewards:} Discrete pairwise outcomes from LMSYS Chatbot Arena human evaluations.
    \item \textbf{Threshold:} Silhouette-optimal, selected without reward labels. Effect size is stable across a sweep of candidate thresholds (Section~\ref{sec:validation_methodology}).
    \item \textbf{Data independence:} PCA trained on RouteLLM battles (\texttt{routellm/gpt4\_judge\_battles}); evaluation on LMSYS general prompts. Different data sources, sampling periods, and prompt populations---disjoint by provenance.
    \item \textbf{High-D structure:} Weak in 384D (silhouette $= 0.057$). PC1 extracts a moderate signal from a noisy space; the ``clusters'' are regions of the PC1 axis with different outcome distributions, not well-separated groups in embedding space.
    \item \textbf{Causal mechanism:} Not ablated. Correlational patterns suggest RLHF alignment effects, but alternative explanations remain possible.
    \item \textbf{Generalizability:} The 19.2\% High PC1 proportion is specific to this holdout. The 1M dataset shows $\sim$5.9\% in the corresponding spatial region, suggesting the holdout may over-represent strict-constraint prompts.
\end{itemize}

\paragraph{Connection to routing evaluation.}
This experiment establishes a \emph{necessary condition}: the router's feature space contains model preference signal.
Whether this signal is \emph{sufficient} for practical routing gains---and whether the bandit can exploit it safely under distribution shift---is the empirical question addressed in the routing evaluation (Table~\ref{tab:routing_results}).
