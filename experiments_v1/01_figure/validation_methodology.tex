\subsection{Validation Methodology}
\label{sec:validation_methodology}

We validate the routing signal finding through a direct correlation test with a distribution-free null baseline.
All analyses use the held-out test set exclusively ($N=750$), with PCA trained on independent data.

\subsubsection{Experimental Design}

\paragraph{Analysis pipeline matches the router.}
BanditGPT's \texttt{FeatureService} encodes prompts with a sentence transformer (\texttt{all-MiniLM-L6-v2}) and compresses the 384D embeddings to 33 dimensions via PCA.
LinUCB then regresses these features against per-model rewards to predict which model will perform best.
Our validation directly tests the input to this regression: we compute the Spearman rank correlation between the PCA's first principal component (PC1) and the reward gap $(R_{\text{GPT-4-Turbo}} - R_{\text{Mixtral}})$.
This is a lower bound on the full feature vector's predictive power, since the router uses all 33 components.

\paragraph{Null baseline.}
To rule out projection artifacts---any 384D-to-2D linear projection may find \emph{some} correlated direction---we compute $|\rho|$ for $N{=}100$ independent random orthonormal projections (QR-decomposed, $384 \to 2$) and compare the Router PCA $|\rho|$ to this null distribution.
If the Router PCA correlation falls within the random distribution, the signal is artifactual; if it greatly exceeds it, the PCA concentrates genuine task-relevant variance.

\paragraph{Data independence (no contamination).}
The PCA training data and held-out evaluation data are \emph{entirely independent datasets} with no overlap by construction:
\begin{itemize}[leftmargin=*,noitemsep,topsep=0pt]
    \item \textbf{PCA training data:} 80K prompts from the \texttt{routellm/gpt4\_judge\_battles} HuggingFace dataset~\cite{routellm}, a curated collection of pairwise battles used by RouteLLM.
    \item \textbf{Held-out evaluation data:} 750 prompts from the LMSYS Chatbot Arena general prompt pool, collected during a different time period with a different sampling procedure.
\end{itemize}
\noindent These two datasets share the same model pair (Mixtral vs.\ GPT-4-Turbo) but originate from \textbf{different data sources, different sampling periods, and different prompt populations}.
The PCA has never seen any evaluation prompt because the two collections were produced independently.
No decontamination or exclusion step is needed---the datasets are disjoint by provenance, not by post-hoc filtering.

\subsubsection{Statistical Tests}

\paragraph{Primary metric: Spearman rank correlation.}
Reward gaps take exactly three values ($\{-1, 0, +1\}$), making the Spearman $\rho$ well suited: it tests monotonic association, makes no distributional assumptions, and handles ties naturally.
Critically, this metric directly tests the question the bandit needs answered: \emph{do the features predict the direction of model preference?}
\begin{itemize}[leftmargin=*,noitemsep,topsep=0pt]
    \item \textbf{Spearman $\rho$} (PC1 vs.\ reward gap): Primary metric with exact $p$-value.
    \item \textbf{Null distribution of $|\rho|$:} Computed over 100 random projections, providing a distribution-free baseline.
\end{itemize}

\paragraph{Supplementary tests.}
\begin{itemize}[leftmargin=*,noitemsep,topsep=0pt]
    \item \textbf{Mann-Whitney $U$-test:} Non-parametric ordinal test on a median split, confirming the Spearman result through a group comparison.
    \item \textbf{Outcome distribution:} Win/tie/loss proportions documenting preference heterogeneity.
\end{itemize}

\subsubsection{Design Rationale}

\paragraph{Why Spearman instead of clustering.}
The bandit performs regression on continuous features, not clustering.
A clustering-based analysis (threshold $\to$ contingency table $\to$ Cram\'er's $V$) introduces unnecessary researcher degrees of freedom: the threshold criterion, minimum cluster size, and clustering dimensionality.
Spearman $\rho$ tests the same hypothesis---features predict preference---without any of these choices.

\paragraph{Why PC1 only.}
The router uses all 33 PCA components, but PC1 captures the most variance by construction.
Testing PC1 alone provides a \emph{conservative} lower bound on the full feature vector's predictive power.
If the bandit gains routing value from higher components, that strengthens the case.

\paragraph{Multiple comparisons.}
The primary analysis computes a single correlation ($\rho$ for PC1 vs.\ reward gap) and compares it against a single null distribution (100 random projections).
No multiplicity correction is needed for this one-hypothesis design.
The supplementary Mann-Whitney test and outcome analysis are confirmatory, not hypothesis-generating.

\subsubsection{Stratification and Generalizability}

\paragraph{Holdout construction.}
The holdout ($N=750$) was created via stratified sampling across category, complexity, and difficulty (Appendix~\ref{app:stratification}).
The difficulty dimension is derived from oracle reward statistics (mean and variance), which introduces an indirect dependence on the outcome variable into the sampling design.
This enriches the holdout for prompts with clear model preferences.
The \emph{existence} of the correlation is robust (Router PCA exceeds all 100 random projections on the same holdout); the \emph{magnitude} of $\rho$ in deployment will depend on the user's prompt distribution.

\subsubsection{Summary}

\begin{enumerate}[leftmargin=*,noitemsep,topsep=0pt]
    \item \textbf{Correlation-based design:} Spearman $\rho$ directly tests whether features predict model preference---matching how the bandit uses features
    \item \textbf{Null baseline:} 100 random orthonormal projections provide the null distribution of $|\rho|$
    \item \textbf{Data independence:} PCA trained on RouteLLM battles (separate dataset from holdout); no contamination
    \item \textbf{Conservative:} PC1 only; the router uses all 33 components, so the full signal is at least as strong
    \item \textbf{One hypothesis:} No multiplicity correction needed
    \item \textbf{Generalizability:} Stratified holdout enriches for signal; production magnitude is deployment-dependent
\end{enumerate}
