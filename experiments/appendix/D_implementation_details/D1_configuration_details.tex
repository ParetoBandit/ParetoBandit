\subsection{Configuration Details}
\label{app:config}

This section documents all configurable parameters of the banditGPT library router
(\texttt{src/bandit\_gpt/router.py}) and the specific values used in each experiment.
Library defaults are listed alongside experiment values to enable both reproduction
of paper results and deployment with the production library.

\paragraph{Implementation Notes.}
\begin{enumerate}[leftmargin=*,noitemsep]
    \item \textbf{Initialization-Only Regularization:} The default
    \texttt{init\_lambda}$=1.0$, \texttt{update\_lambda}$=0.0$ pattern provides
    cold-start stability via $A_0 = I$ while allowing $O(d^2)$ Sherman--Morrison
    updates at runtime (4$\times$ faster than $O(d^3)$ with runtime regularization).

    \item \textbf{Cost Mechanism:} Cost awareness is implemented at the expert level
    via \texttt{cost\_penalty} in each LinUCB expert, which penalizes arm costs within
    the UCB score: $\text{Score} = \hat{r} + \alpha\sigma - \lambda c$.
    The CorrallingRouter's \texttt{model\_costs} field stores cost metadata for
    reference but does not perform reward shaping; cost--quality trade-offs are
    controlled entirely through the expert-level $\lambda$.

    \item \textbf{Loss Decay (Non-Standard Corralling):} The \texttt{loss\_decay}
    parameter is a practical extension of the standard Corralling algorithm
    (Agarwal et al., 2017) that decays the cumulative squared losses used to
    compute adaptive per-expert learning rates.  This prevents stale variance
    estimates from dominating under distribution shift but means the standard
    $O(\sqrt{K T \ln K})$ regret bound applies only approximately. The
    theoretical analysis in Appendix~\ref{appendix:mathematical_foundations}
    assumes standard Corralling ($\texttt{loss\_decay}=1.0$); the experiments
    in this paper also use $\texttt{loss\_decay}=1.0$.
\end{enumerate}

\subsubsection{Cost Penalty Sweeps}

\paragraph{Figure~4 ($K{=}2$).}
The Pareto frontier sweeps 15 cost penalty values:
\begin{equation*}
\lambda \in \{0.0,\; 0.01,\; 0.02,\; 0.05,\; 0.1,\; 0.2,\; 0.25,\; 0.3,\; 0.35,\; 0.4,\; 0.45,\; 0.5,\; 1.0,\; 2.0,\; 5.0\}
\end{equation*}
with 50 independent seeds per $\lambda$ value (750 total runs).
The RouteLLM baseline uses 28 threshold values $\tau \in [0.0, 1.0]$.

\paragraph{Figures~6 and 8 ($K{>}2$).}
Both sweep 11 cost penalty values over the $K{=}5$ and $K{=}10$ portfolios:
\begin{equation*}
\lambda \in \{0.0,\; 0.005,\; 0.01,\; 0.02,\; 0.05,\; 0.1,\; 0.2,\; 0.5,\; 1.0,\; 2.0,\; 5.0\}
\end{equation*}
with 20 independent seeds per $(\lambda, K)$ pair.
Figure~8 additionally sweeps three methods (banditGPT, LinTS with warmup priors,
LinTS tabula rasa) across the same grid, yielding $11 \times 20 \times 2 \times 3 = 1{,}320$ total runs.
