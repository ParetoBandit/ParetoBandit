\subsection{Catastrophic Failure Detection: 5-Model Portfolio}
\label{appendix:catastrophic_failure}

\subsubsection{Motivation: Automatic Failover as a Secondary Benefit}

Production LLM systems face a critical challenge: \textbf{models can catastrophically fail with minimal warning}. API endpoints crash, providers silently update models with quality regressions, or traffic shifts to domains where warmup priors perform poorly.

\textbf{The Question}: Does Corralling---designed primarily for safe expert hedging and contextual routing---provide useful automatic failover when a model catastrophically fails? And how does this scale with portfolio size?

\subsubsection{Experimental Setup}

\paragraph{Why $K=5$?}
With $K=2$ models, catastrophic failure detection is a trivial binary tracking problem: a simple EMA tracker just needs to learn ``model A bad, model B good'' from per-model averages. With $K=5$, post-failure routing becomes \emph{contextual}: the optimal policy must redistribute traffic across 4 remaining models based on prompt features. Each non-failing model excels in a different region of context space, so per-model averages cannot distinguish which alternative is best for a given prompt.

\paragraph{Production Router Components.}
\begin{itemize}
    \item \textbf{CostAwareLinUCBRouter} (warmup expert): Initialized with 43-model evaluation priors for all five portfolio models (Llama-3.1-8B, Mixtral-8x7B, Gemini-2.5-Flash, Claude-Sonnet-4, GPT-4.1)
    \item \textbf{CostAwareTabulaRasaRouter} (tabula rasa expert): Cold-start LinUCB with ridge regularization for all 5 models
    \item \textbf{CorrallingRouter}: Coordinates experts with importance-weighted meta-learning via selection tokens
\end{itemize}

All 5 models have informed warmup priors. Both experts explore freely across all models.

\paragraph{Three-Phase Scenario.}
Context-dependent reward environment (orthogonal context directions per model, noise $\sigma=0.08$):

\begin{itemize}
    \item \textbf{Phase 1 ($t=0$--$100$):} All 5 models healthy
    \item \textbf{Phase 2 ($t=100$--$300$):} GPT-4.1 catastrophically fails ($\mu=0.15$, Cohen's $d\approx 5.0$)
    \item \textbf{Phase 3 ($t=300$--$500$):} GPT-4.1 recovers
\end{itemize}

Corralling settings: $\eta=0.3$, $\gamma=0.05$. Baselines: Oracle, Static GPT-4.1, EMA Tracker ($\alpha=0.15$, $\epsilon=0.1$).

At $K{=}5$, EMA outperforms banditGPT during failure ($\Delta{=}{-}0.106$), but at $K{=}10$ the gap closes entirely ($\Delta{=}{+}0.003$). EMA degrades as $K$ grows because its exploration budget ($\epsilon/K$) thins across more models, while Corralling's contextual experts become more valuable as the post-failure routing decision becomes higher-dimensional.

\subsubsection{Interpretation}

Catastrophic failure detection is a \textbf{secondary safety benefit} of the Corralling mechanism, not its primary design objective. The formal detection rate (5\%, based on meta-learner weight shift) understates banditGPT's actual response: the per-arm UCB updates within each expert implicitly reduce traffic to the failed model, achieving 0.753 failure-phase reward despite the meta-learner not formally ``detecting'' the failure. For pure model-level failure detection, dedicated monitoring (e.g., EMA tracking, CUSUM) should complement Corralling. The gap closure from $K{=}5$ ($\Delta{=}{-}0.106$) to $K{=}10$ ($\Delta{=}{+}0.003$) confirms that at larger portfolios, Corralling's contextual routing fully compensates for its slower meta-level adaptation.
