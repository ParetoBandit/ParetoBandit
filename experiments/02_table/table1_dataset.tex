\textbf{Why these datasets.}
The warmup split uses RouteLLM's battle corpus (\texttt{routellm/gpt4\_judge\_battles})~\cite{ong2024routellm}, containing 80K human preferences between Mixtral and GPT-4-Turbo. We use it to establish reproducible warmup priors aligned with public benchmarks.
Evaluation splits (dev and holdout) draw from the LMSYS Chatbot Arena~\cite{zheng2023lmsys}, maintaining the same model pair to isolate prompt distribution effects.

\textbf{How they are used.}
Warmup data trains a PCA projection (384$\rightarrow$32) for context compression and generates LinUCB priors ($\mathbf{A} \in \mathbb{R}^{33 \times 33}$, $\mathbf{b} \in \mathbb{R}^{33}$), yielding a pre-trained belief for online refinement.
The dev set calibrates hyperparameters ($\gamma$-scaling, $\alpha$-scheduling), while the holdout set evaluates standard online bandit learning~\cite{lattimore2020bandit} across the full interaction sequence.

\textbf{Production impact.}
The PCA and priors ship as lightweight artifacts ($<$1\,MB), mitigating the cold-start problem without costly data collection or proprietary training.
The Corralling meta-learner (Section~\ref{sec:corralling}) manages adaptation if the deployment distribution diverges.
Crucially, the learned routing signal transfers to unseen prompts (Spearman $\rho = 0.370$, $p < 0.0001$, 2.6$\times$ vs.\ random, Figure~\ref{fig:lmsys_holdout_structure}).
Online Sherman--Morrison updates adapt priors dynamically at $O(d^2)$ per observation.

\textbf{Data integrity.}
Warmup and evaluation datasets are independent by provenance.
Automated deduplication removed 243 incidental overlaps (0.24\%) between the two LMSYS-based sources.
Dev and holdout sets employ stratified sampling across category, complexity, and difficulty for representative coverage.
