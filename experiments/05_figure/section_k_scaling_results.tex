\subsection{Corralling Enables Recovery from Catastrophic Failure
(Figure~\ref{fig:catastrophic_failure})}
\label{sec:catastrophic_failure}

\paragraph{Motivation.}
Production LLM deployments face a distinctive risk: a model that was
previously high-quality may suddenly degrade due to API outages,
safety-filter misfirings, or provider-side model regressions.
Static routing policies---including supervised baselines that train once
and freeze---are inherently blind to such shifts: they continue routing
to the degraded model, causing a catastrophic quality collapse.
This experiment tests whether Corralling's meta-learning provides
\emph{automatic failover} without manual intervention.

\paragraph{Setup.}
We evaluate on \textbf{real prompts and embeddings} from the holdout
set ($n \approx 1{,}500$), cycling through the full set once per phase
($T \approx 4{,}500$ total steps, 20 seeds):
\begin{enumerate}[leftmargin=*]
    \item \textbf{Healthy} (steps $0$--$n$): all models at normal
          quality.  Rewards are real ground-truth evaluations from the
          multi-judge panel.
    \item \textbf{Failure} (steps $n$--$2n$): GPT-4.1 (the best static
          model) drops to near-zero quality ($R \approx 0.10$),
          simulating an API outage, safety-filter misfiring, or model
          regression.  All other models retain their real rewards.
    \item \textbf{Recovery} (steps $2n$--$3n$): GPT-4.1 returns to
          normal (real rewards restored).
\end{enumerate}
Because prompts and embeddings are real, the warmup priors are meaningful:
the router's contextual routing decisions during the failure phase must
redistribute traffic based on actual prompt difficulty, not just ``avoid
the failed model.''

We compare six methods:
\textbf{BanditGPT} (Corralling + warmup priors),
\textbf{warmup-only} (no Corralling; priors only),
\textbf{tabula rasa} (no priors, no Corralling),
\textbf{static} (always GPT-4.1),
\textbf{EMA tracker} ($\varepsilon$-greedy with exponential moving averages),
and \textbf{oracle} (per-step clairvoyant).

The experiment reveals three key findings:

\begin{enumerate}[leftmargin=*]
    \item \textbf{Automatic failover.}
    When GPT-4.1 fails, the Corralling meta-learner detects the reward
    degradation within a small number of steps and shifts probability
    mass from the warmup expert (whose priors still favour GPT-4.1) to
    the tabula rasa expert (which adapts to the new reward landscape).
    BanditGPT maintains substantially higher quality during the failure
    phase than the static baseline, which collapses catastrophically.

    \item \textbf{Corralling is necessary, not just priors.}
    The warmup-only ablation (no Corralling) cannot adapt: it continues
    to trust the now-stale priors that favour the failed model.
    This demonstrates that Corralling's expert-switching mechanism---not
    just the warmup priors---is the key ingredient for non-stationary
    robustness.

    \item \textbf{Graceful recovery.}
    When GPT-4.1 recovers, the meta-learner shifts weight back to the
    warmup expert, restoring the original routing quality.  The recovery
    is symmetric: the same mechanism that detects failure also detects
    recovery, without requiring any environment-specific heuristics.
\end{enumerate}

\paragraph{Practical implications.}
In production, model failures are not hypothetical---they are routine
(API rate limits, provider outages, model version regressions).
Corralling provides a principled, \emph{automatic} failover mechanism
that does not require monitoring dashboards, manual intervention, or
pre-specified fallback rules.  The meta-learner continuously evaluates
whether the informed expert (warmup priors) or the adaptive expert
(tabula rasa) is providing better routing decisions, making BanditGPT
inherently robust to the non-stationarity of real-world LLM
ecosystems.
